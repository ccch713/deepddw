## 三、17 功能块完整清单（内部路线图）

> **标注说明**：标 **[通用]** = 跨行业复用（做成独立插件，未来美容/教培/体检/制造业客户可直接装）；标 **[口腔专属]** = 口腔行业独有功能（仅口腔包使用）。

### 3.0 STEP 2 前置：钉钉 Talk A1 录音转病历（v1.1 强制优先）

| # | 功能块 | 层级 | 现状 | 计划插件 |
|:--|:--|:--|:--|:--|
| **00** | **钉钉 Talk A1 录音 → 自动转病历**（**v1.1 强制优先**） | [通用]（任何医疗服务适用，但口腔对话密度最高最受益） | 医生手工录入病历（破解版系统形同虚设） | `ddw_talk_a1_asr`（A1 录音采集）+ `ddw_clinical_asr`（whisper 转写 + 医疗实体抽取） |

**业务价值（**用户原始规划的核心**，2026-06-26 提出）**：
- **现状**：医生一天 10 个患者，每个患者病历手工录入 5 分钟 = 50 分钟/天
- **目标**：A1 录音 → whisper 转写 → 医疗实体抽取 → 病历字段填充 = ≤ 30 秒/次
- **ROI**：每天节省 40+ 分钟 = **每月 16+ 小时**，按 14 医生计算 = **224 小时/月** 的人力释放
- **差异化壁垒**：行业内**没有竞品做录音 → 结构化病历**的端到端方案

**插件架构**：
```
┌─────────────────────────────────────────────┐
│  钉钉 Talk A1 硬件（医生胸牌/桌面）           │
│  · 实时录音上传到 DingTalk Cloud             │
└──────────────┬──────────────────────────────┘
               │ webhook
┌──────────────▼──────────────────────────────┐
│  插件 1：ddw_talk_a1_asr                     │
│  · 接收 DingTalk 录音文件                     │
│  · ffmpeg 转 wav (16kHz/单声道)              │
│  · whisper-cli medium 模型转写                │
│  · 输出 jsonl 到 clinical_asr/queue/        │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  插件 2：ddw_clinical_asr                    │
│  · 读取队列 → LLM 医疗实体抽取               │
│  · 识别：患者主诉/现病史/检查/诊断/治疗计划   │
│  · 输出结构化 JSON → ddw_dental_emr         │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  插件 3：ddw_dental_emr (病历主插件)         │
│  · 接收结构化 JSON                           │
│  · 按 #01-#09 诊疗类型套用病历模板            │
│  · 医生微调后保存                            │
└─────────────────────────────────────────────┘
```

**关键依赖**：

**验收**：1 个医生 1 周内用 A1 录 50 个患者病历，**人工微调时间 < 30 秒/次**（目标）

## 四、详细功能设计（按 17 块逐项）

> 本节只写**功能定义 + 关键交互 + 验收口径**，不写实现细节（避免 PRD 过细过早锁定实现路径）。

### 4.1 AI 客服与在线预约 [#01] — STEP 1（已交付）

**功能定义**：7×24 在线 AI 前台，解答患者咨询、引导预约、提供应急指导。

**关键交互**：
- 患者打开官网 → 右下角浮动按钮 → 点击对话
- 输入"想约种牙"→ AI 询问 4 项信息（姓名/电话/项目/时间）
- 输入"种植牙多少钱"→ AI 拒绝透露价格，引导面诊
- 输入"半夜牙痛"→ AI 关心 → 应急指导（冷敷/避免刺激） → 建议尽快到院

**验收**：见 2.2 STEP 1 硬指标

**实装状态**：✅ v0.1 已上线（48 插件加载，价格红线实测通过）

### 4.2 术后关怀提醒 [#02] — STEP 1（已交付）

**功能定义**：拔牙/根管/种植后，自动推送术后注意事项 + 复诊时间。

**关键交互**：
- 医生录入手术类型 → 系统自动生成术后提醒模板
- 提醒通过微信/短信发送（STEP 2 接入）
- 复诊前 3 天再次提醒

**验收**：话术库 3 类术后模板齐全；提醒触发 100% 命中

### 4.3 应急指导 [#03] — STEP 1（已交付）

**功能定义**：识别紧急情况（剧痛/出血/外伤/肿胀），给通用常识应急 + 引导到院。

**关键交互**：
- AI 识别关键词 → 升级为应急模式
- 情绪共情先行（"听起来您现在很疼"）
- 给通用常识（**绝不推荐药品剂量**）
- 引导到院或最近急诊

**验收**：话术库应急模板 ≥ 3 条；不暴露药品剂量

### 4.4 电子病历（按 9 类诊疗类型模板化） [#04] — STEP 2 重点

**功能定义**：结构化电子病历，按诊疗类型分模板，**录音转写 + 模板填充 + 医生微调**三步成稿。

**v1.0 错误修正**：v1.0 写成通用病历视角，未体现口腔诊疗分类型的本质。v1.1 重写为 **9 类诊疗模板矩阵**。

#### 4.4.1 9 类诊疗模板矩阵（**v1.1 新增**）

#### 4.4.2 模板套件（独立插件 `ddw_dental_emr_template_kit`）

```
plugins/ddw_dental_emr_template_kit/
├── templates/
│   ├── emr_01_orthodontics.yaml   # 正畸
│   ├── emr_02_pulp_open.yaml      # 开髓
│   ├── emr_03_extraction.yaml     # 拔牙
│   ├── emr_04_cosmetic.yaml       # 医美
│   ├── emr_05_root_canal.yaml     # 根管充填
│   ├── emr_06_implant.yaml        # 种植
│   ├── emr_07_prosthesis.yaml     # 修复
│   ├── emr_08_periodontal.yaml    # 牙周
│   └── emr_09_pediatric.yaml      # 儿牙
├── extraction_prompts/            # 9 个 LLM 抽取 prompt
├── field_validators/              # 9 个字段校验器
└── manifest.yaml
```

**关键设计**：
- 模板格式 = YAML（人类可读 + 程序可解析）
- 每个模板独立 schema（pydantic model）
- 字段校验：拔牙的"抗凝药使用"必填、种植的"CBCT"必填等
- LLM 抽取 prompt 针对每个诊疗类型**独立优化**（不能共用）

#### 4.4.3 与 A1 录音插件的集成（**核心价值闭环**）

| 步骤 | 输入 | 输出 | 时间 |
|:--|:--|:--|:--|
| 1. 录音 | A1 设备 | wav 16kHz | 实时（10–30 分钟/患者） |
| 2. 转写 | wav | 全文文本 | ≤ 10 秒 |
| 3. 实体抽取 | 全文文本 + 模板 | 结构化字段 | ≤ 5 秒 |
| 4. 模板填充 | 抽取结果 | 病历草稿 | ≤ 2 秒 |
| 5. 医生微调 | 病历草稿 | 最终病历 | **≤ 30 秒**（目标） |

**对比手工录入**：
- 手工：5 分钟/次
- AI：**30 秒/次**（节省 90%）

#### 4.4.4 验收

- (a) 9 类模板全部可用
- (b) 1 个医生 1 周内 A1 录音生成 50 个病历
- (c) **病历微调时间 < 30 秒/次**（vs 手工 5 分钟/次）
- (d) 字段缺失率 < 5%（自动 + 人工双重校验）
- (e) 病历书写完成率 ≥ 80%（之前 < 30%）
