## 第 2 页 · 痛点：企业 AI 落地难在哪

### 5 个真实的"翻车现场"

| 序号 | 痛点 | 真实场景 | 损失 |
|---|---|---|---|
| ① | **多模型混乱** | 老板让用 ChatGPT，安全要求用 DeepSeek，IT 私心跑 Ollama，3 套 API 各自一套密钥 | Token 成本失控，审计空白 |
| ② | **插件绑死** | 买了某 SaaS 的"AI 助手"，想换 OCR 厂商 → 数据迁移要 3 个月 | 供应商锁定，越用越贵 |
| ③ | **本地部署难** | 厂区数据不能上公有云 → 厂商只能"私有化"，报价 80 万起 | 中小企业被排除 |
| ④ | **员工用不起来** | 推了 3 个月钉钉机器人，日活不到 8%，还不如 Excel | 数字化变成 IT 自嗨 |
| ⑤ | **新旧系统割裂** | 已有 ERP / MES / WMS，AI 工具进不来也出不去 | 又一座信息孤岛 |

### 根本问题
> 当前市面上的"AI 平台"都是 **应用层**（聊天机器人、知识库工具），不是 **底座层**。
>
> 企业需要的是「打地基」，不是「买装修」。

## 第 5 页 · 技术架构：Python 栈 + Docker PG + CLI 管理

### 7 层架构图

```
LAYER 0 · 接入层（IM 适配器）
  ├─ 钉钉 Stream WS（主入口，已实现）
  ├─ 飞书（Phase 2）
  └─ 企微（Phase 2）

LAYER 1 · 网关与中间件
  ├─ API Versioning / JWT + PIN + SMS 三态认证
  ├─ TenantMiddleware（多租户隔离）
  └─ Hot Reloader（配置热更新）

LAYER 2 · 核心引擎
  ├─ Message Router（IM → LLM/插件）
  ├─ Plugin Manager（注册/沙箱/版本）
  └─ ⚡ EventBus（进程内 → Redis Pub/Sub）

LAYER 3 · LLM Gateway ★
  ├─ MiniMax M3（默认锁死）
  ├─ DeepSeek V4 Pro（复杂分析）
  └─ Ollama 16B（本地兜底）

LAYER 4 · 业务插件层
  ├─ 受信任插件：进程内加载
  └─ 第三方插件：JSON-RPC 子进程沙箱

LAYER 5 · 数据抽象层
  ├─ SQLAlchemy + Alembic（6 引擎等深适配）
  ├─ 进程内缓存 → Redis 缓存
  └─ Billing / Licensing Metering

LAYER 6 · SDK 与生态
  ├─ Plugin SDK + i18n + Test Framework
  ├─ Marketplace Protocol（.ddwplugin）
  └─ 一键安装脚本
```

### 技术栈清单（与 PRD v5.4 一致）

- Python 3.11+ / FastAPI 0.110+ / SQLAlchemy 2.0+（Async）
- PostgreSQL 15（Cloud）/ SQLite 3.40+（Standalone）
- 6 引擎等深抽象：PG / MySQL / MariaDB / SQLite / SQL Server / Oracle
- 禁止使用：LangChain / LlamaIndex（保持代码可控）

## 附录 · 讲解时的 3 个常见提问

**Q1：你们和钉钉/飞书的 AI 助手有什么区别？**
> 钉钉的"智能伙伴"是钉钉内置的，你的数据被钉钉拿走；
> DDW 的数据在你自己的服务器上，钉钉只是消息通道。
> 类比：钉钉 = 租房子，DDW = 买地盖房子。

**Q2：我们公司已经买了飞书企业版，还要用 DDW 吗？**
> 要的。飞书/钉钉是"办公协同平台"，DDW 是"AI 业务中台"。
> 飞书发通知，DDW 处理业务（病历、错题、生产数据）。
> 类比：飞书 = 微信，DDW = 微信公众号后台。

**Q3：4C8G 的服务器能跑几个插件？**
> 实测：4C8G 单机可承载 50 个并发用户 + 5 个插件。
> 推荐生产环境：8C16G（200 用户 / 10 插件）。
> 超大规模：分布式（PostgreSQL 主从 + Redis 集群），可扩展到 5000 用户。
