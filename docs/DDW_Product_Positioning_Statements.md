## 一、正式产品定位（适合知识库 / 产品总览 / 投资材料）

**DDW AI Hub 是以插件为业务能力载体，以 Tool 为最小可执行能力，以 Skill 为操作方法，以 SOP 为流程编排，以数字员工为执行主体，以 MCP 为内外连接协议，以 Code CLI 为客户开发入口的企业 AI 能力平台。**

---

## 二、官网短文案（适合首页 Hero / 产品入口）

### A. 一句式（最精炼）

**DDW AI Hub 是一套支持企业自行开发、装配、授权、运行和治理数字员工的企业 AI 能力底座。**

### B. 两段式（适合官网首页）

**一句话：**  
DDW AI Hub 不是一个带插件的聊天平台，而是一套企业 AI 能力底座。

**承接句：**  
它以插件承载业务能力，以 Tool 暴露最小可执行动作，以 Skill 沉淀操作方法，以 SOP 编排复杂流程，以数字员工作为岗位执行主体，以 MCP 对接外部系统与智能体，以 Code CLI 支撑客户自研插件的开发、测试和上线。

### C. 客户可快速理解的口语版

**DDW AI Hub 就像企业的 AI 操作系统——插件提供能力，技能定义做法，流程规定步骤，数字员工上岗执行，MCP 负责和外部系统连接，Code CLI 让客户也能自己扩展系统。**

---

## 三、产品专页文案（适合 DDW 专页 / 宣讲页）

### 标题建议

- 主标题：**DDW AI Hub · 企业级 AI 能力底座**
- 副标题：**插件 · Tool · Skill · SOP · 数字员工 · MCP · Code CLI 一体化平台**

### 开头段落

企业想要的不是另一个只能对话的 AI 产品，而是一套能把 AI 真正落进业务流程的能力底座。  
DDW AI Hub 围绕“**插件、Tool、Skill、SOP、数字员工、MCP、Code CLI**”建立统一能力模型，帮助企业把 AI 从聊天窗口升级为可开发、可装配、可授权、可运行、可治理的数字员工体系。

### 七层能力解释（适合专页结构化展示）

| 层级 | 名称 | 客户价值 |
|---|---|---|
| L1 | 插件 Plugin | 业务能力载体，可安装、可升级 |
| L2 | Tool | 最小可执行动作，便于调用、授权和监控 |
| L3 | Skill | 操作方法沉淀，把经验变成可复用做法 |
| L4 | SOP | 流程编排，把复杂任务变成可追踪闭环 |
| L5 | 数字员工 | 岗位执行主体，把能力组装成可上岗员工 |
| L6 | MCP | 内外连接协议，让平台能力和外部系统互通 |
| L7 | Code CLI | 客户开发入口，让客户也能开发自己的插件 |

### 结尾价值句

**DDW AI Hub 帮企业完成从“AI 能聊天”到“AI 能上岗”的跃迁。**

## 五、建议形成的统一口径

如果后续只能选一句做统一传播口径，我建议采用：

**DDW AI Hub 是一套支持企业自行开发、装配、授权、运行和治理数字员工的企业 AI 能力底座。**

理由：
1. 比“企业 AI 能力平台”更聚焦；
2. 直接回答了“它到底帮客户干什么”；
3. 同时涵盖开发、装配、授权、运行、治理五个关键动作；
4. 更适合 B2B 客户理解，避免只停留在“平台”这种模糊词。
