## 一、设计目标

### 1.1 核心目标

| 目标 | 说明 |
|:-----|:-----|
| **多端可用** | 网页浏览器 + 飞书/钉钉/企微内置浏览器 + 泛微OA嵌入 |

| **官网体验** | 官网（ddw-ai.com）可直接体验 demo，降低获客门槛 |
| **企业级** | 多租户、权限管理、审计日志、数据隔离 |

### 1.2 使用场景矩阵

| 场景 | 入口 | 用户 | 核心功能 |
|:-----|:-----|:-----|:---------|
| 企业管理员 | 浏览器 → DDW 管理后台 | IT管理员/决策者 | 插件管理、用户管理、LLM配置、数据分析 |
| 企业员工 | 飞书/钉钉/企微机器人 | 普通员工 | AI对话、知识查询、流程审批 |

### 4.1 集成架构总览

```
                    ┌─────────────────┐
                    │   DDW AI Hub     │
                    │   (核心平台)      │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
    ┌─────────▼──────┐ ┌────▼─────┐ ┌─────▼────────┐
    │  适配器层        │ │ Webhook  │ │  嵌入层        │
    │  (Adapter)      │ │ Receiver │ │  (Embed)      │
    └─────────┬──────┘ └────┬─────┘ └─────┬────────┘
              │              │              │
    ┌─────────▼──────────────▼──────────────▼────────┐
    │              企业平台接入层                        │
    ├──────────┬──────────┬──────────┬───────────────┤
    │  飞书     │  钉钉     │  企微     │  泛微OA        │
    │  Feishu  │  DingTalk │  WeCom   │  Weaver E-Cology│
    └──────────┴──────────┴──────────┴───────────────┘
```

### 4.2 四大平台对接策略

#### A. 飞书（Feishu / Lark）

| 维度 | 方案 |
|:-----|:-----|
| **认证** | OAuth 2.0 + App Access Token |
| **消息** | 飞书机器人（Webhook / Event Subscription） |
| **嵌入** | 飞书小程序 或 飞书工作台网页应用 |
| **API** | 飞书开放平台 REST API |
| **用户同步** | 通讯录 API 同步组织架构 |
| **数据流** | 用户@机器人 → 飞书Event → DDW API → AI回复 → 飞书消息 |

#### B. 钉钉（DingTalk）

| 维度 | 方案 |
|:-----|:-----|
| **认证** | OAuth 2.0 + App Key/Secret |
| **消息** | Stream 模式（WebSocket 长连接，推荐） |
| **嵌入** | 钉钉工作台 H5 微应用 |
| **API** | 钉钉开放平台 REST API |
| **用户同步** | 通讯录 API 同步部门/员工 |
| **数据流** | 用户@机器人 → DingTalk Stream → DDW API → AI回复 → DingTalk消息 |

#### C. 企业微信（WeCom）

| 维度 | 方案 |
|:-----|:-----|
| **认证** | OAuth 2.0 + Corp ID/Secret |
| **消息** | 企微机器人 Webhook + 消息回调 |
| **嵌入** | 企微工作台网页应用 |
| **API** | 企微 REST API |
| **用户同步** | 通讯录 API 同步 |
| **数据流** | 用户@机器人 → WeCom回调 → DDW API → AI回复 → WeCom消息 |

#### D. 泛微 OA（Weaver E-Cology）

| 维度 | 方案 |
|:-----|:-----|
| **认证** | 泛微 SSO（Token/Cookie） |
| **嵌入** | OA 内嵌 iframe（DDW 管理页面嵌入 OA 门户） |
| **API** | 泛微 REST API（流程/文档/人事） |
| **数据同步** | 双向同步（DDW ↔ OA 数据库） |
| **典型场景** | 智能审批（AI辅助审批决策）、知识问答（OA文档库检索）、智能填单 |
| **数据流** | OA页面内嵌DDW iframe → DDW API → AI分析 → 结果回写OA |

### 4.3 嵌入模式设计

**模式一：iframe 嵌入（推荐，最简单）**
```html
<!-- 泛微OA / 飞书工作台 / 钉钉工作台 内嵌 DDW -->
<iframe 
  src="https://ddw-ai.com/chat?token=xxx&user=yyy" 
  style="width:100%; height:100vh; border:none;"
  allow="microphone">
</iframe>
```
- 优点：实现最简单，各平台都支持
- 缺点：无法完全定制外观，有安全限制
- 适用：初期快速上线

**模式二：Web Component 嵌入**
```html
<!-- 各平台页面中引入 DDW Web Component -->
<script src="https://ddw-ai.com/widgets/ddw-chat.js"></script>
<ddw-chat 
  api-base="https://ddw-ai.com/api" 
  theme="light"
  user-id="xxx">
</ddw-chat>
```
- 优点：可定制外观，更好的集成体验
- 缺点：需要各平台支持自定义脚本
- 适用：深度集成场景

**模式三：API 直连 + 原生 UI**
- 各平台用原生 UI 调用 DDW API
- 最好的用户体验，但开发成本最高
- 适用：长期战略，核心客户深度定制

### 4.4 推荐实施路径

| 阶段 | 集成方式 | 目标平台 | 周期 |
|:-----|:---------|:---------|:-----|
| **Phase 1** | iframe 嵌入 + Webhook | 飞书 + 钉钉 | 2周 |
| **Phase 2** | Webhook 双向 + 用户同步 | 企微 + 泛微OA | 3周 |
| **Phase 3** | 原生集成 + 深度定制 | 全平台 | 持续迭代 |

## 六、技术选型

### 6.1 前端框架决策

| 方案 | 优点 | 缺点 | 推荐 |
|:-----|:-----|:-----|:-----|
| **纯 HTML/CSS/JS** | 零依赖、加载快、易部署 | 复杂交互难维护 | ✅ Phase 1 |
| **Vue 3 + Vite** | 中国生态好、轻量、渐进式 | 需要构建步骤 | ✅ Phase 2 |
| **React + Next.js** | 生态丰富、SSR支持 | 包体大、学习曲线 | ❌ 不推荐 |

**推荐路径**：Phase 1 用纯 HTML/CSS/JS（与现有代码一致），Phase 2 迁移到 Vue 3。

## 九、安全设计

### 9.1 认证方案

| 场景 | 认证方式 |
|:-----|:---------|
| 管理后台 | JWT + PIN + SMS（已有） |
| OA/IM 嵌入 | OAuth 2.0 授权码流程 |
| 官网 Demo | 临时 Token（15分钟过期） |

### 9.2 数据安全

- iframe 嵌入使用 `sandbox` 属性限制权限
- 跨域请求使用 CORS 白名单
- 敏感配置（API Key）不暴露给前端
- 审计日志记录所有关键操作
