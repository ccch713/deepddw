套装推荐包的商业意义

  • 企业 IT 不用自己研究"哪几个插件组合才完整"
  • 套装打折（85 折/7 折）→ 企业方购买意愿更高
  • 插件作者主动加入套装 → 互相导流
  • 套装自动算价：比单买便宜 ≈ 买了不亏
  • 一人公司不用手动配置套装——manifest.yaml 声明后自动显示

技术实现成本

  • manifest.yaml 新增 ecosystem 段：~20 行配置
  • 市场前端解析 ecosystem 数据 → 自动绘制图谱
  • 套装算价：价格 = SUM(插件单价) × multiplier
  • 一套代码支持 N 个解决方案图谱
  • 你不需要为每个行业手动编目录——插件作者自己填

③ 渠道商 / 服务商管理体系

一人公司不需要自己跑销售。渠道商体系让你坐在家里收分润。

🏢 大账号（总代/区域代理）
小账号 A（FDE 前端交付）
小账号 B（销售）
小账号 C（售后支持）
↓ 以上所有账号同时拥有"开发者"身份（可发布插件）

分润比例（你定的）

  • 底座平台：公开价 60% 给渠道
  • 示例：企业版 ¥19,999 → 渠道拿 ¥11,999 → 你收 ¥8,000
  • 市场插件：5% 给渠道
  • 示例：¥100 插件 → 渠道拿 ¥5
  • 渠道利润主要靠底座（大单），插件是"引流品"
  • 大账号分润可再设下级比例（大账号自由设置小账号比例）

渠道商后台功能

  • 注册申请 → 自动审核（或你手动通过）
  • 仪表盘：客户数 / 活跃插件 / 当月分润
  • 创建/管理小账号（设置权限角色）
  • 客户续费提醒 + 到期预警
  • 分润明细下载（Excel / PDF）
  • 品牌定制（可选：投放白标版本）
  • 技术支持工单（转给插件作者）
  • 所有渠道商也同时是开发者

一人公司的零人工运作

  • 渠道注册 → 自动审核（信用检查 + 企业认证）
  • 分润计算 → 系统自动按订单算清
  • 分润提现 → 月度自动结算（支付宝转账或银行代付）
  • 争议处理 → 工单系统 + 插件作者仲裁
  • 你不需要任何销售团队、客服团队
  • 渠道商帮你做地面推广，你躺收平台抽成

渠道商的开发者身份很重要：渠道商在帮企业部署 DDW 底座时，如果发现某个行业插件缺了某个功能 → 他直接自己写一个 → 发布到市场 → 卖给他的客户。这样渠道商从"只卖不产"变成了"卖 + 产"，生态正向循环。你什么都不用做。

🤖 AI 爬虫 / 自动盗取插件代码

威胁AI 爬虫批量下载市场插件源码，用于训练或转卖
防御• 市场 API 限流：每个 IP/开发者账号每日最多下载 50 次
• 插件代码仅对已登录开发者提供下载（非登录只能看业务页）
• 付费插件下载前校验许可证（社区版只能下免费插件）
• 下载日志记录 + 异常下载告警（24h 内 200+ 次 → 自动风控）
• 代码可选项：插件作者选择是否公开源码（闭源插件只发布编译后的 .ddwplugin）

🔍 反编译 / 逆向工程

威胁企业 IT 拿到 .ddwplugin 后解包、反编译、破解许可证检查
防御• 插件打包时可选 pyarmor / pyoxy 混淆编译（插件作者自愿开启）
• 运行时 License 双重验证：平台层验一次 + 插件层再验一次
• 付费插件内嵌 静默心跳：安装后定期向市场 API 发起匿名心跳（仅含安装量计数，不含业务数据）
• 同一许可证在多设备激活 → 自动标记异常 → 通知插件作者
• 插件的核心业务逻辑建议用 C 扩展（.so/.pyd）打包（可选）

☣️ 代码供应链投毒攻击

威胁恶意开发者发布带后门的插件 → 企业安装后数据泄露
防御• 插件包签名强制：每个 .ddwplugin 必须用开发者私钥签名，市场 API 验签后才上架
• 沙箱隔离（§18.7）：第三方插件默认跑在 JSON-RPC 子进程中，无法直接访问主机文件系统
• 权限声明强制：manifest.yaml 中声明所需权限 → 安装时询问用户授权
• 静态代码扫描（可选）：提交到市场时自动扫描已知恶意模式
• 社区举报 + 审核下架机制：任何用户可举报插件 → 自动临时下架 → 人工核查
• ⚠️ 如果你发布官方插件（medical_records 等），你自己签名的插件不做此限制（信任你自己的签名的代码）

🌐 网络安全 / 数据安全攻击

威胁DDoS / SQL 注入 / XSS / 中间人攻击 / 数据泄露
防御• 已有：Caddy HTTPS + UFW + CrowdSec + fail2ban（ECS 已封 80/443 外全部端口）
• 新增：市场 API 再加一层 Cloudflare（免费版即可：WAF + DDoS 防护）
• 所有 API 请求 JWT 认证（§18.1 已在 PRD 中）
• SQLAlchemy ORM 防注入（ORM 已自带参数化查询，无需额外代码）
• 插件沙箱资源限制：max_memory_mb / max_cpu_percent / timeout（§18.7 已在）
• 数据分级：病历类数据强制 AES-256 加密存储（数据库层 + 文件层）
• 审计日志记录所有数据访问操作（谁 + 何时 + 什么数据 + 操作类型）
• 离线模式安全加固：Standalone 部署建议关掉公网端口，仅内网使用
