## 三、SSE 流式优化要点

- **端点**：`POST /api/v1/plugins/ddw_online_cs/chat/stream`，`data: {"session_id":...}` 开场 → `data: {"token":"..."}` 逐 token
- **前端**：site-common.js ReadableStream 实时消费，fetch 非流式降级兜底
- **性能实测**：首 token **363ms**（外网含 TLS + 网关 + MiniMax 推理），完整问答 ~2.7s
- **流式路径同样写对话日志**（source=`kb+llm_stream`）——自进化数据源不丢
- **网关调用链**：`_ask_llm` 第一优先 `core.llm_gateway.gateway.chat()`（fallback 链 minimax→deepseek→ollama + 用量统计），异常自动回退直连 minimaxi（`/text/chatcompletion_v2`），再失败 kb_fallback

## 四、消耗统计闭环（本次补的关键缺口）

**原状态**：客服已走网关 + `UsageTracker.record()` 只写**内存**，`llm_usage_records` 表 0 条——落库从未实现。

**实现**：
1. `core/llm_gateway/usage.py`：record() 后 fire-and-forget sqlite 写入（best-effort，异常只 debug 日志不阻塞）
2. `core/api/admin.py`：`GET /api/v1/admin/llm/usage?days=N`（admin JWT 保护；汇总 + by_provider 分组 + recent 20 条）
3. 管理后台 `saas-admin.html` 概览页"LLM 网关消耗"卡片（调用/tokens/成本/Provider/最近记录）

**实测闭环**：客服问答 → 网关 → MiniMax → 落库 `(1, minimax, MiniMax-M3, 1154 in, 290 out, ¥0.0058, rule=default, ok=1)`

**坑（必记）**：`llm_usage_records` 表为历史遗留，`id BIGINT NOT NULL + PRIMARY KEY(id)` 非自增 → INSERT 必须显式 `SELECT COALESCE(MAX(id),0)+1`，否则 `NOT NULL constraint failed`。
