## 二、发现并修复的问题（6 项）

1. **CrowdSec bouncer 双实例**（start-crowdsec.sh 自启 + systemd 同时拉起）→ 脚本移除冗余启动，依赖改为 crowdsec-custom.service，单实例验证。
2. **系统漏洞**：ubuntu-advantage-tools / ubuntu-pro-client 系列 + bouncer 0.0.34→0.0.36 → apt 升级，0 待更新。
3. **云备份多天失败**：根因 = systemd-resolved 对 hbr 端点域名解析超时 → hbrclient exit 16 崩溃循环（restart counter 3646 ≈ 5 天）→ 备份中断（7/25、7/29-8/3 两次窗口）。8/3 13:08 自愈，8/4、8/5 备份已成功（20.8GB）。
   - 加固：/etc/hosts 写死 hbr 双端点 IP（公网 39.101.x.x + 内网 100.100.0.106）
   - 加固：/etc/cron.d/dns-health-check 每 5 分钟探测，systemd-resolved 假死自动重启
4. **官网 502（严重）**：ECS 重启后 geo-IP DROP 拦截 Docker 网桥流量（172.19.0.x 不在 china ipset）→ Caddy 容器无法连 172.19.0.1:8500 → ddw.9cio.com 持续 502（`dial tcp i/o timeout`）。本机 nc 127.0.0.1 测不出（lo 流量不受影响）。
   - 修复：`iptables -I INPUT 4 -s 172.16.0.0/12 -j ACCEPT`（docker-bridge-pre-geoip）
   - 持久化：docker-bridge-pre-geoip.service（systemd 开机自恢复）+ iptables-save 双保险
   - 规范 INPUT 链：1 CROWDSEC → 2 ESTABLISHED → 3 lo-accept → 4 docker-bridge → 5 DROP china → 6+ ufw
5. **ddw-core 服务失守**：Restart=on-failure 在收到 SIGTERM 后不自动重启 → 外部 nohup 手动拉起（03:49 事件）→ 改为 **Restart=always**（TERM 模拟验证 8 秒内自动拉起），systemd 成为唯一守护者。
6. **authorized_keys 去重**（3→2）+ 残留包清理 + iptables 持久化快照更新。
