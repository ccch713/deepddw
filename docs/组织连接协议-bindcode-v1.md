# 组织连接协议 · bindcode v1（Organization Binding Protocol）

> 版本：v1.0（2026-10-09 随《DDW 分层部署与 CB 端联动 PRD v1.1》D4 决策发布）
> 性质：**开放协议规范**。任何实现本协议的服务器（下称"企业服务器"）均可被 DDW AI 助手系列 App 识别为组织后端并被用户绑定连接。
> 参考实现：DDW relay-credits 插件（服务端实现不开源，协议开放）。
> 许可：本文档本身可自由引用与实现；实现者无需获得授权，但需遵守 §6 安全要求。

---

## 1. 协议目标与角色

```
┌──────────────┐   ①绑定码（扫码/手输）   ┌──────────────────┐
│  DDW AI 助手  │ ───────────────────────▶ │    企业服务器        │
│  （C 端 App） │   ②绑定（bind）          │ （deepDDW / Hub /   │
│              │ ◀─────────────────────── │  任何本协议实现）     │
└──────────────┘   ③组织身份+服务地址       └──────────────────┘
                                        ▲
                        ④绑定码签发（管理端） │
                                        ┌──────────────────┐
                                        │  组织管理员          │
                                        └──────────────────┘
```

三个角色：

- **C 端 App**：不持有任何上游 LLM 凭证；绑定前连官方托管，绑定后可在个人后端与企业服务器之间一键切换（切换 provider 不改变绑定状态，仅用户主动"断开"才解绑）。
- **企业服务器**：协议的实现方，承担绑定后用户的推理成本与数据落地。**LLM 供给完全由部署者自行配置**（任意 OpenAI 兼容供应商/自建网关），本协议不隐含、不要求任何特定模型供应商或官方渠道。
- **组织管理员**：在企业服务器上创建组织、签发绑定码、管理成员与额度。企业额度开放对象=已绑定成员，由绑定码用次与吊销机制控制。

## 2. 绑定码（Bind Code）规范

### 2.1 格式

```
DDWORG-<b64url(payload)>.<sig16>
```

- `payload = org_id + "|" + exp_ts + "|" + nonce`，UTF-8；
  - `org_id`：组织标识（实现方自定，建议 `org_` + 8 hex 以上，全局唯一）；
  - `exp_ts`：Unix 秒级过期时间戳；
  - `nonce`：随机串（≥8 hex），保证同一分钟内多次签发互不相同；
- `b64url`：URL-safe Base64，去除 `=` padding；
- `sig16`：`HMAC-SHA256(org_secret, payload)` 十六进制摘要的**前 16 字符**；
- `org_secret`：仅存在于服务端的组织级密钥（≥32 字节随机），签发与校验都用它，**永不下发 App**。

### 2.2 校验规则（实现方必须全部满足）

1. **格式解析**：拆分失败 → 拒绝（403）；
2. **签名比对**：重算 HMAC 与 `sig16` 常数时间比较（防伪造）；
3. **时效**：`exp_ts` 已过 → 拒绝（410）；
4. **用次**：服务端记录每个 code 的使用计数，超过签发时声明的 `max_uses` → 拒绝（409）；
5. **吊销**：服务端可删除 code 记录使其立即失效（404）。

推荐默认：时效 15 分钟、`max_uses` 50；高安全场景（如公开渠道发放）用一次性码。

### 2.3 承载方式

二维码内容即绑定码字符串本身（或 `https://<企业服务器域名>/bind?c=<绑定码>` 的跳转 URL）。用户扫码零手输。

## 3. 服务端接口规范

所有接口走 HTTPS；产品侧调用携带服务间共享密钥头 `X-Product-Key`（App 本身不接触该头，由 App 的产品后端持有——**绑定链路上任何一步都不交换上游 LLM 凭证**）。

### 3.1 绑定

```
POST /api/v1/relay/credits/org/bind
{ "user_id": "<App侧用户标识>", "code": "<绑定码>" }
→ 200 { "bound": true, "org": { "org_id", "name", "plan", "pool_credits", ... } }
→ 403 malformed / bad signature    410 expired    409 usage exhausted / already bound
```

语义：校验通过则建立 `user_id ↔ org_id` 绑定关系（用户同时至多归属一个在绑组织；换绑须先解绑）。

**org 对象可选字段**（v1 向后兼容扩展，供 App 直连企业后端使用；实现方按能力返回，App 须容忍缺省）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `server_base_url` | string | 本实例 LLM 端点 base（OpenAI 兼容），App 绑定后可切换直连 |
| `access_token` | string | 成员级访问凭证（绑定流程下发，吊销/解绑即失效；区别于组织密钥 org_secret，后者永不出现于任何响应） |
| `models` | string[] | 可用模型 ID 列表（App 展示档位时参考） |

### 3.2 解绑

```
POST /api/v1/relay/credits/org/unbind
{ "user_id": "..." }
→ 200 { "bound": false }
```

语义：解绑后用户回官方托管/个人计费。**个人侧资产（余额、本地数据）必须完整保留**——这是协议的强制要求，不是建议（员工信任是本协议存在的前提）。

### 3.3 组织状态查询

```
GET /api/v1/relay/credits/org/me?user_id=...
→ 200 { "bound": bool, "org": {...} | null, "org_consumed_total": int }
```

### 3.4 计费语义（抽象要求）

绑定后该用户的请求成本由企业侧承担。参考实现采用"**组织额度池优先、池尽整笔回退个人余额**"（不停服原则）；实现方至少须保证：组织额度策略可配置、个人余额不被组织消耗、流水可按组织聚合对账。

### 3.5 管理端接口（实现方自便，协议不强制路径）

创建组织 / 签发绑定码 / 额度池充值 / 成员与用量报表。参考实现走 `X-Admin-Key` 且仅内网暴露。

## 4. App 侧行为约定

- 绑定入口位于 设置 → 高级 → 连接企业服务器（不打扰个人用户默认体验）；
- 绑定成功后显示"已连接 \<组织名\>"，可随时断开；
- **绑定是身份关系，不是后端锁定**：用户可在 个人模式（官方托管/自定义模型/个人记忆体）与 企业模式（server_base_url 直连 + 企业知识上下文）之间一键切换，切换不改变绑定状态、不迁移不删除任何本地个人数据（记忆体始终在本机）；
- 断开即回官方托管且解除绑定关系，本地个人数据不删除；
- App 不解析、不存储 `org_secret`，只透传绑定码；`access_token` 若下发则随解绑/吊销失效。

## 5. 隐私与数据边界（强制）

- 个人/组织双空间物理隔离：**用户未绑定时的一切个人数据不得进入企业侧**；
- 组织报表只到聚合层（按人计费对账所必需的最小明细除外，且须在企业隐私政策中披露）；
- 不得向雇主提供员工个人行为的画像分析。

## 6. 安全要求（实现方清单）

| 项 | 要求 |
|---|---|
| 传输 | 全链路 HTTPS |
| 密钥 | `org_secret` 仅存服务端，≥32 字节随机，支持轮换（轮换后旧码在时效内仍有效，属预期） |
| 校验 | HMAC 常数时间比较；拒绝理由区分度最小化（可统一返回 invalid code） |
| 端点 | 绑定端点须有限速；管理端点不得暴露公网 |
| 日志 | 只落元数据（org_id/user_id/时间/结果），不落请求正文 |

## 7. 版本化与兼容承诺

- 本版为 **bindcode v1**，码前缀 `DDWORG-` 即版本标识的一部分；
- v1 兼容承诺：DDW AI 助手系列 App 对 v1 码的扫码/手输行为至少维持至 v2 发布后 12 个月；
- v2 及以后变更将保持 payload 向后可解析（新增字段用 `|` 追加，不改变既有字段语义）；
- 实现方应在 `/health` 或等价端点声明协议版本：`{"protocol": "bindcode", "version": "1"}`。
