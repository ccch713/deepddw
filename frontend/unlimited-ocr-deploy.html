2环境检查（5 分钟）

一条命令确认 GPU 可用；有问题先解决再往下走

# GPU 是否可见（必须有输出，显示显卡型号与显存）
nvidia-smi

# Python 版本（需 3.10+）
python3 --version

# 磁盘空间
df -h / | tail -1

# 预期输出示例
+-----------------------------------------------------------------------------+
| NVIDIA-SMI 535.154.05   Driver Version: 535.154.05   CUDA Version: 12.2   |
|    0  NVIDIA GeForce RTX 4090      24GB     On  |  ...                     |
+-----------------------------------------------------------------------------+

⚠️ 环境不满足时

  • 无 NVIDIA 显卡 → 停止部署，现场说明硬件需求（推荐 24GB 显存，最低 16GB），安排硬件到位后二次上门或远程部署
  • 驱动版本低 → sudo apt install -y nvidia-driver-535 后重启；或使用客户环境已有的新版驱动
  • Python < 3.10 → sudo apt install -y python3.11 python3.11-venv

3模型就位（10 分钟）

从随行 U 盘拷贝完整模型目录（6.3GB，含权重与代码）

# 1. 创建目录并拷贝（U 盘路径按实际调整）
sudo mkdir -p /opt/uocr && sudo chown $USER /opt/uocr
cp -r /media/$USER/USB/Unlimited-OCR /opt/uocr/

# 2. 核对权重完整性（必须约 6.67GB）
ls -lh /opt/uocr/Unlimited-OCR/model-00001-of-000001.safetensors
# 预期：6672547120 字节 ≈ 6.3GB（6.67GB 二进制）

# 3. 离线可用确认：模型目录包含以下文件即完整
# config.json / tokenizer.json / modeling_unlimitedocr.py / deepencoder.py / processor_config.json ...

4环境安装（15-20 分钟）

SGLang 为推荐后端（吞吐最高）；首次安装含依赖编译，需联网

# 创建虚拟环境
python3.11 -m venv /opt/uocr/venv
source /opt/uocr/venv/bin/activate

# 安装依赖（网络良好约 10 分钟）
pip install -U pip
pip install "sglang[all]>=0.4.4.post3" transformers torch

# 验证安装
python -c "import sglang; print('sglang OK')"

💡 离线/内网环境

客户网络无法访问 PyPI 时：提前在可联网机器执行 pip download "sglang[all]>=0.4.4.post3" -d /opt/uocr/wheels，将 wheels 目录随行携带，现场 pip install --no-index --find-links=/opt/uocr/wheels ... 安装。

5启动服务（10 分钟，含模型加载）

启动后约 60-90 秒完成模型加载；此命令建议保存为 start.sh 脚本

# start.sh
#!/bin/bash
source /opt/uocr/venv/bin/activate
cd /opt/uocr/Unlimited-OCR
python -m sglang.launch_server \
  --model ./ \
  --served-model-name Unlimited-OCR \
  --attention-backend triton \
  --page-size 1 \
  --mem-fraction-static 0.7 \
  --context-length 32768 \
  --trust-remote-code \
  --enable-custom-logit-processor \
  --host 0.0.0.0 --port 8000

✅ 健康检查

# 模型列表
curl http://localhost:8000/v1/models
# 预期返回包含 "Unlimited-OCR"

🧠 推理模式选择

  • base（1024px）：多页 PDF 全保真，生产推荐
  • gundam（640px）：高并发单图，吞吐优先
  • 默认 base；高负载场景可切换

6功能验证（5 分钟）

用客户文档做端到端验证——这一步通过才算部署完成

# 单页图片解析验证（Python）
import base64, requests

img = base64.b64encode(open("sample.png","rb").read()).decode()
r = requests.post("http://localhost:8000/v1/chat/completions", json={
    "model": "Unlimited-OCR",
    "messages": [{"role":"user","content":[
        {"type":"image_url","image_url":{"url":f"data:image/png;base64,{img}"}},
        {"type":"text","text":"OCR the image to Markdown"}
    ]}],
    "max_tokens": 4096
})
print(r.json()["choices"][0]["message"]["content"])

✅ 验收标准

  • 单页解析 ≤ 30 秒返回（24GB 显卡）
  • 输出为正确 Markdown，中文/英文/数字无误
  • 多页 PDF（PyMuPDF 转页 + 一次请求）能完整返回
  • 表格、公式样例正确还原

7批量解析脚本（客户交付模板）

现场交付时可提供此模板，客户 IT 稍作修改即可投产

# batch_ocr.py —— 多页 PDF 批量解析 → Markdown 文件
import fitz, base64, requests, pathlib

API = "http://localhost:8000/v1/chat/completions"
def pdf_to_markdown(pdf_path: str) -> str:
    doc = fitz.open(pdf_path)
    pages = []
    for page in doc:
        pix = page.get_pixmap(dpi=300)   # 300 DPI 高清
        pages.append(base64.b64encode(pix.tobytes("png")).decode())
    r = requests.post(API, json={
        "model": "Unlimited-OCR",
        "messages": [{"role":"user","content":[
            {"type":"image_url","image_url":{"url":f"data:image/png;base64,{p}"}} for p in pages
        ] + [{"type":"text","text":"将以上多页文档整体解析为 Markdown，保持原文结构和阅读顺序"}]}],
        "max_tokens": 32768, "timeout": 600,
    })
    return r.json()["choices"][0]["message"]["content"]

# 用法：python batch_ocr.py 合同.pdf 输出.md
if __name__ == "__main__":
    import sys
    src, dst = sys.argv[1], sys.argv[2]
    pathlib.Path(dst).write_text(pdf_to_markdown(src), encoding="utf-8")
    print(f"完成：{src} -> {dst}")

📌 批量处理建议

  • 单批 ≤ 40 页（模型上下文 32K 上限），超长文档分段处理
  • 扫描件建议 300 DPI；清晰电子 PDF 可用 200 DPI 提速
  • 高并发场景用 gundam 模式 + 多线程请求

8常见错误速查

部署与运行中 90% 的问题都在这里

现象原因处理
nvidia-smi 无输出驱动未装/未加载装驱动 535+ 并重启
启动报 CUDA out of memory显存不足或有进程占用nvidia-smi 查占用；降低并发；确认 16GB+
输出无限重复使用了 llama.cpp 后端（已知 bug）改用 SGLang 后端
vLLM 下数字循环vLLM 兼容问题（官方 issue #87）改用 SGLang 后端
解析超时文档页数过多单批 ≤ 40 页；增大 timeout
手写/票据乱码模型弱项（手写体）诚实说明 + 建议双通道（PaddleOCR 兜底）
加载很慢（数分钟）正常（6.3GB 权重 mmap）提前启动预热，勿现场首次加载
