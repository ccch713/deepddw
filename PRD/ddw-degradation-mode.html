DDW AI Hub · 反盗版：降解模式

针对"老板让IT盗版省钱"的真实对策 · 一人公司可执行

你说的是事实：中国很多中小企业的老板就是让 IT 盗版。POC 报告红字警告没用——老板不在意，IT 也被默许甚至鼓励。我们要面对的真实问题是：不是"怎么阻止盗版"，而是"怎么让盗版比付钱更疼"。

❌ 抛弃的方案：POC 报告红字警告 → 对"老板要求盗版"的场景完全无效
✅ 保留 ① 时间胶囊

RSA 签名时间戳 + 设备指纹。挡住 80% 顺手改时间的。一人公司用 Python cryptography 搞定，30 行代码。

✅ 保留 ② 设备指纹

MAC + 磁盘序列号 hash。挡住重装克隆重新试用的。一样 20 行代码。

❌ 抛弃 ③ POC 报告红字

老板不关心报告颜色。所以 ③ 换成真正的杀手锏：降解模式↓

🔥 核心策略：试用到期 → 插件进入"降解模式"，不停止、不弹窗、让终端用户感到疼

设计理念：

试用到期后，插件不停止工作（停了 IT 有理由重装），而是进入"慢性降解"模式。
降解模式不弹窗、不报错、不提示"试用到期"——让 IT 不好判断是破解失败还是系统 bug。

最终受影响的是终端用户（医生、护士、工人、操作员）——他们每天都用这个系统，降解让他们难受 → 他们找领导投诉 → 领导问 IT 怎么回事 → IT 才知道"原来破解的插件会这样" → 最后选择买正版。

降解行为由插件作者在 manifest.yaml 中配置（灵活、按需）

# plugins/medical_records/manifest.yaml 中的试用配置 trial: duration_days: 7 expired_behavior: degraded # stop | degraded | free_tier degradation: daily_limit: 20 # 每天最多 20 次操作 response_delay_ms: [3000, 8000] # 随机延迟 3-8 秒 data_quality: 0.98 # 2% 概率插入乱码（可逆） watermark: true # 生成的 PDF/报告打水印 skip_probability: 0.1 # 10% 概率"跳过"本次操作 features: - "auto_backup_disabled" # 自动备份功能关闭 - "batch_import_disabled" # 批量导入功能关闭 - "export_disabled" # 导出功能关闭 notify_on_detect: true # 检测到破解迹象时通知插件作者
⏱ 随机延迟 每次操作延迟 3-8 秒。IT 难以判断是"系统慢"还是"破解被限制"。终端用户每天多等几分钟 → 烦躁 → 投诉
📉 每日限额 每天只能做 20 次操作。口腔诊所医生一天看 30-50 个病人 → 下午发现用不了 → 找老板 → 老板找 IT
🔢 数据降质 2% 概率病历 PDF 里出现乱码或水印。医生打印给患者时发现 → 丢面子 → 投诉系统
🔇 静默跳过 10% 概率"跳过"本次保存操作（数据不丢，但这次操作无效）。护士没注意以为保存了 → 下次找不着 → 认为是系统 bug
🔒 功能阉割 自动备份、批量导入、导出等功能在降解模式下隐藏或不可用。IT 发现"少了功能"但说不清少了什么

🧑‍💼 对插件作者（你和其他开发者）

• 降解模式写在 manifest.yaml 里，约 10 行配置
• Plugin SDK 提供 trial_utils 工具函数，开箱即用
• 不需要写反破解代码，不需要懂逆向工程
• 降解行为是"慢性"的，IT 难以确认是因为破解还是系统问题
• 每个插件作者自己决定：病历插件加水印，生产看板加延迟

🏢 对盗版企业（IT + 老板）

• IT 改了时间/改了源码 → 插件虽然能用但慢慢变难用
• IT 排查：是破解导致的还是系统本身的问题？——需要懂源码！
• 终端用户每天抱怨：慢、乱码、丢失操作 → 管理层听到投诉
• 老板最终要算账：员工因系统慢多花的时间 × 工资 = 远高于 ¥1.99-4.99/月
• 最终决策：不如买正版省心

🧑‍🔧 对一人公司（你本人）

• 你不需要做任何执法、追查、诉讼
• SDK 的 trial_utils.py 写一次（约 80 行），永久生效
• 降解行为在插件代码层执行，和平台开源代码分离
• 插件作者（包括你自己）控制自己的插件怎么降解
• 你不和盗版者对抗，让终端用户帮你去施压

🎯 为什么这个策略在现实中有效

• 中国 SME 老板不怕法务、不怕红字、不怕协议条款
• 但老板怕员工投诉 productivity 下降
• 降解模式的延迟 + 限额 + 乱码 = 真实的业务层面疼痛
• 关键是：降解是渐进的、不易诊断的，IT 没法一句话说清"这是因为破解"
• 3-6 个月后，老板自己受不了 → 主动问"能不能买正版"
• 那时 ¥4.99/月对老板来说就是"解决投诉的钱"

🛠 技术上防止降解模式被 IT 绕过的三个措施
IT 的尝试 修改平台源码，注释掉许可证检查 平台层改源码不治本
但降解逻辑在插件层代码里，不在平台层。插件打包为 .ddwplugin，校验逻辑在插件 SDK 的 trial_utils 里。
IT 要绕过降解需要：① 解包 .ddwplugin ② 找到 trial_utils ③ 改掉逻辑 ④ 重新打包 — 每更新一次插件都要重新来一遍。		 对大多数 IT 来说成本太高
IT 的尝试 2 冻结时间（定时回拨） 时间胶囊防回拨
时间胶囊的 trial_end 是市场 API 签名的时间，不是本地时间。平台每次起动时校验签名有效性。如果 IT 把时间跳到未来再跳回来 → 平台检测到时间异常 → 标记为破解 → 降解模式加剧（延迟翻倍、限额减半）。 自动反制，不人工介入
IT 的尝试 3 每 7 天重置系统/新设备指纹 重复消耗 IT 时间
IT 每 7 天要重装一次系统/改一次指纹。终端用户每 7 天要经历一次"重新配置"。IT 一次折腾半天。一个月 2 次 = 1 天白干。他的月薪 ¥8,000 = 日薪 ¥360。插件价格 ¥1.99-4.99/月。IT 一天工资够买 72-180 个月插件。
老板算账：与其让 IT 每月花一天折腾破解，不如 ¥1.99/月买正版。		 经济账算通了
